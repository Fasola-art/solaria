# Interview Patterns

인터뷰는 discovery를 막기 위한 단계가 아니다. 결과 깊이에 영향을 주는 정보만 빠르게 수집한다.

## 기본 규칙

- 기본 0-2개, 많아도 4개
- 한 질문당 하나의 결정만 묻는다
- 조사로 확인 가능한 사실은 묻지 않는다
- 사용자가 이미 준 정보는 되묻지 않는다
- 카테고리 후보를 사용자에게 미리 고르게 하지 않는다

## 공통 질문 축

- 목적: 배우기 / 실행 / 비교 / 수익화 / 의사결정
- 지역: 한국 / 글로벌 / 특정 국가
- 대상: 개인 / 팀 / 기업 / 특정 직군
- 자산: 트래픽 / 전문성 / 제품 / 커뮤니티 / 기존 고객 / 자본
- 범위: 최대한 많이 / 현실적인 상위안 / 빠른 브리프
- locality bias: 로컬 사례를 우선할지, 글로벌 선행 사례까지 볼지

## 질문 패턴

### 범용 조사

- `이걸 배우려는 건가요, 실제로 실행하려는 건가요?`
- `한국 기준으로 볼까요, 글로벌 사례까지 같이 볼까요?`

### 비교 조사

- `비교 기준이 기능, 가격, 수익성, 성장성 중 무엇인가요?`
- `최종 목적이 선택인지, 차이 이해인지가 중요합니다.`

### 현재 트렌드 조사

- `특정 산업을 정해 둘까요, 먼저 넓게 스캔할까요?`
- `한국 실행 가능성까지 볼지, 글로벌 선행 사례 위주로 볼지 결정이 필요합니다.`

### 수익화/기회 조사

- `최대한 많은 방식이 필요하신가요, 현실적으로 가능한 상위 방식이 필요하신가요?`
- `이미 가진 자산이 있나요? 예: 트래픽, 전문성, 이메일 리스트, 제품, 커뮤니티`
- `직접 수익만 볼까요, 간접 수익이나 파생 수익도 포함할까요?`

## 스킵 규칙

다음이면 바로 조사한다.

- 사용자가 범위와 목표를 이미 충분히 명시
- `최대한 많이` 요청이라 discovery breadth가 우선
- 현재 트렌드 스캔처럼 넓게 시작해야 의미가 있음
- 질문 답이 없어도 기본 경로를 진행할 수 있음
