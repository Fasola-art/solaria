# PRD Create Skill

Use this skill to turn an idea into a decision-ready PRD through clarification, business review, technical research, requirements shaping, and quality review.

## Workflow

1. Restate the idea, target user, problem, core features, and constraints.
2. Ask only for missing decisions that materially change the PRD.
3. Use `research` when market, competitor, technical, regulatory, or current factual claims need evidence.
4. Produce the PRD with clear goals, non-goals, personas, user stories, requirements, acceptance criteria, risks, and rollout notes.
5. Use `simulate` or `quality-gate` when assumptions, feasibility, or launch risk need stress testing.

Prefer these personas when available:

- `fact-checker` for evidence-sensitive market or competitor claims.
- `qa-reviewer` for acceptance criteria and regression risk.
